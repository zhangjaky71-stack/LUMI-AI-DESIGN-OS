# LUMI Deep Agents Runtime V1

## Purpose

NODE-29 turns the pinned `deepagents==0.6.12` package into a LUMI-controlled expert execution harness. Deep Agents supplies planning/todo, filesystem offloading, subagents, skills, memory hooks and context management; LUMI remains authoritative for tenancy, permissions, budget, lifecycle, durable Task Graphs, provider routing, sandboxing and provenance.

## Placement

```text
NODE-28 LangGraph agentic_task
        |
        v
DeepAgentTaskExecutor
        |
        +-- NODE-30 AgentConfigResolver (port)
        +-- NODE-31 SkillMaterializer (port)
        +-- ContextBundleProvider (port)
        +-- NODE-22 Model Gateway model adapter
        +-- NODE-25 Tool Gateway wrappers
        +-- NODE-21 trusted backend / sandbox
        +-- NODE-27 RunBudgetMeter
        +-- Result Store
        |
        v
LumiDeepAgentFactory -> deepagents.create_deep_agent(...)
```

The Deep Agent never transitions the Project lifecycle and never becomes the source of truth for business Tasks. Deep Agents todo items are scratch planning only.

## Invocation identity

Every invocation carries authoritative IDs that are constructed outside model input:

- organization id
- project id
- AgentRun id
- task id
- operation id
- actor id
- exact root agent id
- permission scope
- budget limit
- trace id

The model never chooses those values.

## Permission model

`PermissionScope` is an intersection fence, not a suggestion. Runtime grants must be subsets of the exact resolved Agent config. Subagent tools must remain a subset of parent effective tools. Skills cannot widen permissions.

Server-owned scope keys are rejected recursively from Tool Gateway payloads, including organization/project/run/task/operation/actor/permission fields.

## Filesystem

The only virtual namespaces are `/workspace/input`, `/workspace/work`, `/workspace/output`, `/skills`, and `/memory`.

Input and skills are read-only. Work/output are scratch/candidate paths. Memory reads and writes require explicit scopes. Traversal and unknown roots fail closed.

A backend with execute capability is forbidden unless the exact invocation grants `sandbox_execute`. A granted execute capability additionally requires the LUMI Sandbox binding. This prevents a generic Deep Agents backend from silently exposing a host shell.

## NODE-21 relationship

NODE-21 already implements `DeepAgentsSandboxAdapter` against `SandboxRuntimeService` and `DockerSandboxBackend`. NODE-29 treats that as the execute implementation and adds the higher-level role/permission fence. It does not introduce `subprocess`, `os.system`, Docker socket access, or provider secrets into agent-runtime.

## Context architecture

Pinned hard constraints are generated by Context Compiler and injected into a dedicated immutable system-prompt block. Dynamic task/user/material context is source-labeled. Deep Agents may summarize working messages, but summarization is not the only copy of brand/project hard constraints.

Large tool results are offloaded by reference. The model receives a summary and durable ref rather than large binary/raw provider payloads.

## Skills

NODE-29 consumes exact `MaterializedSkill` values. Skill files live below `/skills/<id>/<version>/...`; the factory enables the Deep Agents native skills middleware with `/skills/`. NODE-31 later owns dependency resolution, eval release gates and canonical publication.

## Memory

The `/memory` route is policy controlled. NODE-29 defines read/write scope constraints; a production durable backend remains a separate composition concern. Organization-global writes are not inferred from model intent.

## Subagents

P0 supports specialized leaf experts such as researcher, creative-specialist and critic when NODE-30 resolves them and the invocation allowlist grants them. A child cannot gain tools not held by the parent. Long-running or independently cancellable work must be promoted into TaskGraph + LangGraph instead of hidden inside synchronous delegation.

## Model boundary

Deep Agent config stores a model routing profile, never a provider-native model id. `LumiDeepAgentFactory` accepts only a LangChain-compatible object carrying both Model Gateway and server budget bindings. Provider SDK imports and direct provider HTTP domains are forbidden in NODE-29.

## Budget

Tool calls are fenced before Tool Gateway invocation. The production chat-model adapter must meter every model call through NODE-22/NODE-27. Near-threshold warnings may be included in the trusted permission summary, but the hard stop is server-side.

## Structured output

Every agentic task returns `AgentTaskResult`:

```text
status
summary
decisions
artifact_refs
knowledge_refs
proposed_operations
open_questions
confidence
```

The factory requests structured response format when supported by the pinned Deep Agents contract. Runtime parsing remains mandatory. One repair is allowed; persistent invalid output fails closed.

Proposed operations are proposals only. They are stored for later policy/orchestration decisions and are never executed merely because an agent emitted them.

## NODE-28 handoff

The full result and provenance go to the Result Store. The main LangGraph state only receives durable refs and failure codes. This preserves the NODE-28 rule that Graph State is bounded orchestration state, not a hidden business database or reasoning transcript.

## Provenance

The stored result freezes:

- exact agent id/version/config hash
- Context Bundle ref/hash
- exact skill versions
- exact Tool Gateway tool versions
- model routing profile
- sandbox-execute flag

Paused or replayed runs therefore do not silently change behavior when registries later publish new versions.

## Production gaps

See `reports/nodes/NODE-29/gap-ledger.json`. NODE-30/31 own canonical Agent/Skill publication; Context/Memory/Model-budget and runtime DI remain explicit integration gaps. Hosted CI is external-blocked until the GitHub account can allocate runners.
