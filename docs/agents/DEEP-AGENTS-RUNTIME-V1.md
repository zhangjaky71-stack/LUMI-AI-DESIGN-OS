# LUMI Deep Agents Runtime V1

## Purpose

NODE-29 turns pinned `deepagents==0.6.12` into a LUMI-controlled expert execution harness. Deep Agents supplies scratch planning/todo, context management, filesystem middleware, skills and synchronous subagents; LUMI remains authoritative for tenancy, permissions, budget, lifecycle, durable Task Graphs, provider routing, sandboxing and provenance.

## Placement

```text
NODE-28 LangGraph agentic_task
        |
        v
DeepAgentTaskExecutor
        |
        +-- NODE-30 AgentConfigResolver (port)
        +-- NODE-31 SkillMaterializer (port)
        +-- ContextBundleProvider (port)
        +-- NODE-22 Model Gateway model adapter
        +-- NODE-25 Tool Gateway wrappers
        +-- NODE-21 trusted backend / sandbox
        +-- NODE-27 RunBudgetMeter
        +-- Result Store
        |
        v
LumiDeepAgentFactory -> deepagents.create_deep_agent(...)
```

The Deep Agent never transitions Project lifecycle and never becomes the source of truth for business Tasks. Deep Agents todo items are scratch planning only.

## Invocation identity

Every invocation carries authoritative IDs constructed outside model input:

- organization id
- project id
- AgentRun id
- task id
- operation id
- actor id
- exact root agent id
- permission scope
- budget limit
- trace id

The model never chooses those values.

## Permission model

`PermissionScope` is an intersection fence, not a suggestion. Runtime grants must be subsets of the exact resolved Agent config. Subagent tools remain a subset of parent effective tools. Skills cannot widen tool, sandbox or memory permissions.

Server-owned scope keys are rejected recursively from Tool Gateway payloads, including organization/project/run/task/operation/actor/permission fields.

## Filesystem

The only virtual namespaces are `/workspace/input`, `/workspace/work`, `/workspace/output`, `/skills`, and `/memory`.

Input and skill paths are read-only. Work/output are scratch/candidate paths. Memory reads and writes require explicit scopes. Traversal and unknown roots fail closed.

NODE-29 applies two independent fences:

1. `ScopedWorkspacePolicy` validates the LUMI virtual namespace and execute grant.
2. Deep Agents `FilesystemPermission` rules allow only the exact root/leaf paths needed by the compiled agent and end with a deny-all rule.

A backend with `execute`/`aexecute` is forbidden unless the exact invocation grants `sandbox_execute`. When execute is granted, the backend must carry the LUMI Sandbox binding. This prevents a generic Deep Agents backend from silently exposing a host shell.

## NODE-21 relationship

NODE-21 already implements `DeepAgentsSandboxAdapter` against `SandboxRuntimeService` and `DockerSandboxBackend`. NODE-29 treats that as the execute implementation and adds the higher-level role/permission fence. It does not introduce `subprocess`, `os.system`, Docker socket access, provider secrets or a host-local shell into agent-runtime.

## Context architecture

Pinned hard constraints are generated by Context Compiler and injected into a dedicated immutable system-prompt block. Dynamic task/user/material context is source-labeled. Deep Agents may summarize working messages, but summarization is not the only copy of brand/project hard constraints.

The same immutable constraint block is copied into every allowed specialist subagent system prompt. Delegated task text is explicitly classified as user/workflow input rather than trusted platform policy.

Large tool results are offloaded by reference. The model receives a bounded summary and durable ref rather than large binary/raw provider payloads.

## Skills

NODE-29 consumes exact `MaterializedSkill` values. A skill must resolve to an exact `<skill_id>@<version>` and an exact `/skills/<id>/<version>/SKILL.md` path with a content hash.

The root agent receives only the directories corresponding to its own exact `skill_refs`. Each leaf subagent receives only the directories corresponding to that leaf's exact `skill_refs`; child skills are not implicitly inherited from the parent. Any extra materialized skill that is not referenced by the exact root/allowed-child configuration fails closed.

NODE-31 later owns dependency resolution, eval release gates and canonical publication.

## Memory

The `/memory` route is policy controlled. Root reads/writes require explicit scopes and Deep Agents filesystem permissions mirror those scopes. P0 leaf subagents receive no memory path. Organization-global writes are never inferred from model intent.

A production durable memory backend remains a separate composition concern.

## Subagents

P0 supports specialized leaf experts such as researcher, creative-specialist and critic when NODE-30 resolves them and the invocation allowlist grants them. A child cannot gain tools not held by the parent, cannot write memory in P0, and cannot request sandbox execution through a skill.

Deep Agents' built-in `general-purpose` delegation target is replaced by a deterministic disabled runnable. This prevents the model from bypassing the exact specialist allowlist through an implicit catch-all subagent.

P0 supports root-to-leaf delegation only (`max_depth <= 1`). A run that grants shell/sandbox execution cannot also enable synchronous subagents; work needing both must be promoted to separate durable TaskGraph/LangGraph tasks. Long-running or independently cancellable work is always promoted to TaskGraph + LangGraph rather than hidden inside synchronous delegation.

## Model boundary

Deep Agent config stores a model routing profile, never a provider-native model id. `LumiDeepAgentFactory` accepts only a LangChain-compatible object carrying both Model Gateway and server-budget bindings. Provider SDK imports and direct provider HTTP domains are forbidden in NODE-29.

## Tool boundary

Every business tool is a NODE-25 Tool Gateway wrapper with canonical name/version markers. Scope is injected server-side. A stable framework `tool_call_id` contributes to a deterministic idempotency key, so retries cannot silently create a new side-effect identity.

Large results are normalized/offloaded before re-entering model context.

## Budget

Tool calls hit a server-side budget fence before Tool Gateway invocation and settle afterward. The production chat-model adapter must meter every model call through NODE-22/NODE-27. Near-threshold warnings may be included in the trusted permission summary, but the hard stop is server-side.

## Structured output

Every agentic task returns `AgentTaskResult`:

```text
status
summary
decisions
artifact_refs
knowledge_refs
proposed_operations
open_questions
confidence
```

The root and configured leaf specialists request the same structured response contract. Runtime parsing remains mandatory. One repair is allowed; persistent invalid output fails closed.

Proposed operations are proposals only. They are stored for later policy/orchestration decisions and are never executed merely because an agent emitted them.

## NODE-28 handoff

The full result and provenance go to the Result Store. The main LangGraph state receives only durable artifact/context refs and failure codes. This preserves the NODE-28 rule that Graph State is bounded orchestration state, not a hidden business database or reasoning transcript.

Nested Deep Agent threads are deterministic for run/task/agent exact version and remain separate from the main NODE-28 control-plane thread.

## Provenance

The stored result freezes:

- exact agent id/version/config hash
- Context Bundle ref/hash
- exact root and allowed-child skill versions
- exact Tool Gateway tool versions
- model routing profile
- sandbox-execute flag

Paused or replayed runs therefore do not silently change behavior when registries later publish new versions.
