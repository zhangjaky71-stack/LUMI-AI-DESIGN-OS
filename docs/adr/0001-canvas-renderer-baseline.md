# ADR-0001 — Canvas Renderer Baseline

> Status: ACCEPTED FOR SPIKE / VALIDATING IN NODE-08  
> Date: 2026-08-16  
> Decision Owner: LUMI AI Design OS Architecture V2  
> Related Node: NODE-08

## Context

LUMI needs a desktop-first infinite design canvas that can sustain large scenes, custom interaction semantics, non-destructive Design IR operations, DOM-grade text editing, and later artifact/version/provenance workflows. The renderer must not become the persisted domain model.

NODE-08 evaluates the Architecture V2 baseline:

```text
PixiJS v8 renderer
+ custom camera / viewport
+ custom selection / transform layer
+ DOM text editing overlay
+ renderer-independent SpikeNode JSON adapter
```

The comparison baseline is Konva/react-konva and Fabric.js. This ADR is not a claim that one library is universally superior; it records the fit for LUMI's architecture and the concrete spike implementation.

## Decision

Use **PixiJS v8 as the primary Canvas renderer baseline**, with DOM overlays for professional text input and application chrome. Persisted Design IR remains renderer-independent and is adapted into the Pixi scene graph at runtime.

The spike pins its browser prototype to PixiJS `8.18.1`. The production dependency strategy will be revisited when NODE-47 begins the formal Canvas Engine implementation; NODE-08 intentionally remains an isolated prototype and does not freeze a future package-manager version.

## Architectural boundary

```text
Persisted / serializable SpikeNode or future Design IR
                    ↓
             Renderer Adapter
                    ↓
           Pixi runtime objects
                    ↓
              GPU renderer

DOM overlays ← worldToScreen / screenToWorld → Camera
```

Rules:

1. Pixi `Container`, `Sprite`, `Text`, `Texture`, and renderer objects are runtime-only.
2. Camera transforms are not written into persisted nodes.
3. React/application state will own chrome, commands, inspector state, and metadata; high-frequency pointer transforms remain in the imperative rendering layer.
4. Text editing is performed in a DOM editor positioned from the shared coordinate conversion API, then committed back to normalized data.
5. Image rendering goes through an asset reference/resolver boundary and a bounded texture pool; raw production object-storage URLs are not the domain identifier.

## Spike evidence

The NODE-08 prototype implements:

- infinite pan and wheel/pinch zoom;
- zoom-to-cursor anchor preservation;
- frames / fit-to-scene and frame-selection;
- text, image-reference, and rect nodes;
- click selection and Shift-drag marquee selection;
- node drag, resize handles, rotation;
- layer reordering;
- copy/paste;
- command-based undo/redo prototype;
- offscreen visibility culling;
- lazy image texture loading and explicit release;
- DOM text editor with CJK, emoji, multiline, and composition-event handling;
- renderer-independent node state and camera math;
- browser-measured 2k mixed, 10k simple-shape, 1k image, 1k text/100 rich-text, and 500-selection scenarios.

Measured browser results are generated by GitHub Actions and retained as the NODE-08 workflow artifact rather than being invented in this ADR.

## Comparison

Scores are LUMI architectural-fit judgments from the spike and public library capabilities, not vendor benchmark scores. `5` means best fit for LUMI's target, not universally better software.

| Criterion | PixiJS v8 | Konva / react-konva | Fabric.js |
|---|---:|---:|---:|
| Large-scene renderer headroom | 5 | 3 | 3 |
| Custom scene-graph freedom | 5 | 4 | 4 |
| Native rich text editing | 3 | 3 | 5 |
| Interaction primitives out of box | 3 | 5 | 5 |
| Custom export / rendering freedom | 5 | 4 | 4 |
| React integration convenience | 3 | 5 | 3 |
| Low domain-model lock-in when adapter is enforced | 5 | 4 | 3 |
| LUMI long-term fit | **5** | 4 | 3 |

### Why Pixi wins for LUMI

The product target is not a small canvas widget; it is a custom design operating system with its own Design IR, constraints, artifact history, Agent edits, and potentially very large scenes. Pixi provides a low-level scene graph and GPU-oriented rendering layer while leaving LUMI free to own its domain and interaction model.

The main cost is that selection transforms, rich editor behavior, and text editing require more product engineering than Konva/Fabric. Architecture V2 already expects LUMI to own those semantics, so that cost is acceptable rather than a blocker.

## Fallback rule

The renderer baseline may be changed before NODE-47 only if a reproducible blocker is demonstrated, including one of:

- ordinary ~2k mixed scenes cannot achieve acceptable interactive behavior after reasonable culling/batching;
- 10k stress behavior shows a fundamental renderer bottleneck rather than expected stress degradation;
- DOM overlay coordinate synchronization is unstable across required DPR/browser cases;
- texture lifetime cannot be bounded reliably;
- required export or accessibility architecture is impossible without violating Design IR separation.

If such a blocker appears, Konva is the first fallback for a comparison prototype because it offers stronger built-in transformer/interaction primitives and first-class React ergonomics.

## Known limitations of the spike

- NODE-08 is a technology spike, not the formal Canvas Engine or Design IR.
- Selection bounding boxes are axis-aligned; production rotated multi-selection math belongs to later Canvas nodes.
- The prototype uses generated local textures instead of production asset-storage integration.
- Browser CI currently exercises Chromium on Linux. Edge and Safari-specific manual/hosted validation remains part of the production Canvas browser matrix.
- The spike records browser frame-time measurements but does not claim identical performance on every user machine.
- Rich text is a stress case; professional typography, shaping, font licensing/loading, and exact export fidelity are later nodes.

## Consequences

Positive:

- renderer and persisted domain remain cleanly decoupled;
- high-frequency interaction can avoid React-tree rerenders;
- the architecture can scale toward custom Design IR transforms and Agent-generated operations;
- texture/culling policies remain application-controlled.

Costs:

- LUMI must implement selection/transform/editor primitives rather than receiving a full editor abstraction;
- accessibility and text editing require a disciplined DOM-overlay layer;
- production export fidelity must be tested independently from interactive rendering.

## Revisit

Revisit this ADR at NODE-47 before freezing the production Canvas Engine package/version and again if NODE-55/56 local editing or export requirements reveal a renderer-level blocker.
