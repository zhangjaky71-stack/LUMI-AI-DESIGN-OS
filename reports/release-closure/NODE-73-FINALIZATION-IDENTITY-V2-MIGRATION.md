# NODE-73 Finalization Identity V2 Migration

Status: **SOURCE V2 MIGRATION IMPLEMENTED -> VALIDATING -> BLOCKED_EXTERNAL**

Scope: NODE-73 Release Closure only. This report supersedes the earlier single-SHA Final Acceptance assumptions. It does not introduce NODE-74 and does not change the final release verdict.

## 1. P0 defect corrected

The earlier finalization model implicitly tried to make one Git SHA serve all of these roles:

```text
Source RC SHA
= final evidence/package branch HEAD
= GitHub human-review commit
= live branch-protection head
= Final Decision workflow execution SHA
```

That model is cyclic. A live GitHub approval or branch-protection report tied to commit A cannot be committed back into commit A. Committing the report creates commit B, at which point the report/reviews tied to A are stale.

The same cycle applies to any final decision artifact that is committed back to the branch whose exact SHA the decision is intended to attest.

## 2. Canonical V2 identity model

NODE-73 now uses two explicit identities.

### Source RC SHA

`release_candidate.git_sha` is the product/runtime identity. It is the commit used by:

- six-runtime image build and attestation;
- migrations;
- Production-like Staging;
- Production deployment;
- upstream release decisions;
- 46-scenario evidence.

### Evidence Head SHA

The final `release-closure-p0` commit is the evidence/execution identity. It contains only non-live final evidence, policies, authorization request, V2 package, V2 workflow and V2 source contracts.

Final Decision requires:

```text
GITHUB_REPOSITORY = zhangjaky71-stack/LUMI-AI-DESIGN-OS
GITHUB_REF = refs/heads/release-closure-p0
GITHUB_SHA = Evidence Head SHA
PR #135 head = Evidence Head SHA
live protected release-closure-p0 head = Evidence Head SHA
Source RC SHA is a Git ancestor of Evidence Head SHA
```

Source RC and Evidence Head are deliberately allowed to differ.

## 3. Committed package is pre-approval only

The V2 package is generated by:

```text
scripts/final-acceptance-assembler-v2.py
```

Canonical output:

```text
reports/final-acceptance/<release-id>/release-manifest-v2.json
reports/final-acceptance/<release-id>/acceptance-evidence.json
```

The committed package freezes:

- Source RC identity;
- Production deployment manifest;
- six upstream decisions;
- 46-scenario evidence;
- repository-governance policy;
- V2 authorization request;
- configured approval-principal policy through the authorization request;
- operational handoff.

The committed package must keep all five release approvals at `PENDING`.

It must not contain either:

```text
release_authorization
repository_governance
```

as live/head-bound reports.

`validate_final_acceptance_package_v2.py` enforces this fail-closed rule.

## 4. Human approval V2

Added:

```text
final/acceptance/release-approval-policy-v2-template.json
final/acceptance/release-authorization-request-v2-template.json
scripts/capture_release_authorization_v2.py
```

The request freezes the Source RC, role-principal policy and operational handoff but contains no Evidence Head and no APPROVED result.

At Final Decision time, `capture_release_authorization_v2.py` reads PR #135 live and requires:

- PR head equals Evidence Head;
- each accepted review is `APPROVED` for the exact Evidence Head commit;
- the reviewer is a configured human principal;
- PR author and bots are rejected;
- only the actor's latest decisive review counts;
- at least three distinct approvers;
- Engineering != Security;
- Security != Release Owner.

The runtime authorization report records Source RC and Evidence Head separately and is never committed back to the branch.

## 5. Repository governance V2

A committed governance observation tied to the same branch HEAD was removed from the canonical package model.

The V2 package instead freezes:

```text
final/acceptance/repository-governance-policy-template.json
```

Final Decision captures GitHub protection state live using the read-only `RELEASE_GOVERNANCE_TOKEN` and requires the strong `LUMI_RELEASE_PROTECTION_PROFILE_V1` profile for both NODE-73 release refs.

The live `release-closure-p0` head must equal Evidence Head, not Source RC.

## 6. Final Decision V2

Added:

```text
scripts/final-acceptance-decision-v2.py
```

The outer decision performs, in order:

1. validate the committed V2 package;
2. bind execution context to repository/ref/Evidence Head;
3. capture and validate live strong repository governance;
4. capture and validate live Evidence-Head GitHub approvals;
5. prove Source RC is an ancestor of Evidence Head with `git merge-base --is-ancestor`;
6. create an in-memory release projection containing the live-derived five `APPROVED` statuses;
7. invoke the stable 46-scenario `final-acceptance-gate.py`;
8. bind canonical input SHA-256 values, live governance report hash, live authorization report hash, Source RC, Evidence Head and workflow execution identity into `final-decision-v2.json`.

Runtime-only outputs are Actions artifacts:

```text
runtime-v2/repository-governance-live.json
runtime-v2/release-authorization-live.json
final-decision-v2.json
```

They must not be committed back to `release-closure-p0`.

## 7. Canonical workflow migration

`.github/workflows/final-acceptance-gate.yml` is V2-only for manual Final Decision:

- accepts only `release-manifest-v2.json`;
- runs only from `refs/heads/release-closure-p0`;
- checks out exact `${{ github.sha }}`;
- uses `fetch-depth: 0` for ancestry proof;
- requires `source-contract` PASS;
- requires `canonical-lock-gate` PASS;
- only `final-decision` receives `pull-requests: read`;
- uses only the ephemeral `GITHUB_TOKEN` for PR-review reads;
- invokes `validate_final_acceptance_package_v2.py` and `final-acceptance-decision-v2.py`;
- does not invoke the V1 final package/decision path.

A Final Decision therefore cannot run in parallel with a failed source or canonical dependency gate.

## 8. Final package producer V1 bypass removed

A migration audit found `.github/workflows/assemble-final-acceptance.yml` still produced the V1 package.

It has now been migrated to V2-only behavior:

- V2 authorization request input instead of precomputed authorization;
- fixed governance policy input;
- V2 assembler and V2 package validator;
- output `release-manifest-v2.json`;
- all approvals must remain `PENDING`;
- live governance/authorization fields are forbidden;
- workflow runs only from `release-closure-p0`;
- exact dispatch SHA checkout with full history;
- remote branch head is checked against `GITHUB_SHA` before assembly and again before push;
- no force push;
- immutable checkout/setup-python Action pins.

The package-producer workflow was also added to `production/release-actions/pins-v1.json` as a release-critical workflow, and `validate_release_workflow_permissions.py` now scopes its `contents: write` permission only to the assemble job.
