# NODE-29 — Acceptance Evidence

Status: **IMPLEMENTED → VALIDATING → BLOCKED_EXTERNAL**

This node implements the Deep Agents expert harness that runs inside the NODE-28 LangGraph agentic-node boundary. It does not own Project lifecycle, the business Task Graph, provider credentials, Agent Registry publication, or Skill Registry publication.

## Implemented runtime contract

- Exact `DeepAgentTaskRequest` with authoritative organization/project/run/task/operation identity.
- `PermissionScope` for canonical tools, sandbox execute, memory read/write scopes, and subagent allowlist.
- `ResolvedAgentConfig` / `ResolvedSubagent` runtime contracts that expect NODE-30 to freeze exact versions.
- `MaterializedSkill` contract with exact version, content hash, path, required tools/permissions, and provenance.
- `PinnedContextBundle` with immutable hard constraints, task context, source refs, exact version, and content hash.
- Structured `AgentTaskResult` with status, summary, decisions, artifact/knowledge refs, proposed operations, open questions, and confidence.
- `DeepAgentProvenance` freezing agent/context/skill/tool/model/sandbox facts.

## Hard boundaries

### Model

The factory accepts only LangChain-compatible model objects marked as both NODE-22 Model Gateway-bound and server-side run-budget-bound. Provider-native model strings and provider SDKs do not appear in NODE-29 runtime code.

### Tools

Deep Agent tools are generated by `LumiToolGatewayProvider` only. Tenant/run/task/operation/permission fields are server-owned and recursive attempts to put those fields into model tool payloads are rejected before Tool Gateway invocation. A stable framework tool-call id produces a deterministic idempotency key.

### Filesystem / execute

Virtual roots are limited to:

- `/workspace/input` — read only
- `/workspace/work` — read/write scratch
- `/workspace/output` — read/write candidate output
- `/skills` — read only exact skill materialization
- `/memory` — scoped by memory read/write policy

Path traversal is rejected. A backend exposing `execute`/`aexecute` is rejected when `sandbox_execute=false`. When execute is granted, the backend must carry the LUMI sandbox-execute binding. NODE-21 already contains `DeepAgentsSandboxAdapter` backed by `SandboxRuntimeService`/`DockerSandboxBackend`; production package/DI composition remains explicit gap `DEEP-SANDBOX-005`.

### Context / prompt injection

The system prompt has fixed platform safety, trusted role, generated permission summary, immutable Context Compiler pinned constraints, and selected exact skills. Dynamic task/user context is source-labeled and explicitly treated as data where appropriate. Pinned project constraints are not dependent on message summarization/compaction.

### Skills / subagents

Native Deep Agents skills are enabled with `/skills/`; materialized skill requirements cannot expand effective tool/sandbox/memory permissions. Subagents are exact resolved definitions and can only use a subset of parent tools plus the invocation subagent allowlist. Long-running/cancellable work remains a TaskGraph/LangGraph responsibility.

### Budget / large tool results

Tool calls hit a server budget meter before invocation and settle afterward. Large tool results pass through an offloader so the model receives a bounded summary/reference rather than an unbounded payload. Model objects must be pre-wrapped by the production Model Gateway/budget adapter.

### Structured handoff

The runtime prefers Deep Agents/LangChain `response_format` and always validates the machine result. One repair is allowed through `StructuredOutputRepairer`; a second invalid result fails closed. `proposed_operations` are persisted in the result record and never automatically executed or copied into NODE-28 Graph State.

## NODE-28 integration

`DeepAgentTaskExecutor.execute(state)` is compatible with the NODE-28 agentic TaskPort seam. It resolves the exact runtime config, exact skills, Context Compiler bundle, compiles the Deep Agent, invokes a stable nested thread, validates/stores the structured result, and returns only safe NODE-28 state keys:

- `artifact_refs`
- `context_refs`
- `errors` when the agent reports failure

The nested thread id is deterministic for run/task/agent exact version and is separate from the main control-plane thread.
