# NODE-29 — Acceptance Evidence

Status: **IMPLEMENTED → VALIDATING → BLOCKED_EXTERNAL**

This node implements the Deep Agents expert harness inside the NODE-28 LangGraph agentic-node boundary. It does not own Project lifecycle, the business Task Graph, provider credentials, Agent Registry publication, or Skill Registry publication.

## Implemented runtime contract

- Exact `DeepAgentTaskRequest` with authoritative organization/project/run/task/operation identity.
- `PermissionScope` for canonical tools, sandbox execute, memory read/write scopes and subagent allowlist.
- `ResolvedAgentConfig` / `ResolvedSubagent` contracts expecting NODE-30 to freeze exact versions and immutable config hashes.
- `MaterializedSkill` with exact version, content hash, `SKILL.md` path, required tools/permissions and provenance.
- `PinnedContextBundle` with immutable hard constraints, task context, source refs, exact version and content hash.
- Structured `AgentTaskResult` with status, summary, decisions, artifact/knowledge refs, proposed operations, open questions and confidence.
- `DeepAgentProvenance` freezing agent/context/skill/tool/model/sandbox facts.

## Hard boundaries

### Model

The factory accepts only LangChain-compatible model objects marked as both NODE-22 Model Gateway-bound and server-side run-budget-bound. Provider-native model strings and provider SDKs do not appear in NODE-29 runtime code.

### Tools

Deep Agent tools are generated by `LumiToolGatewayProvider`. Tenant/run/task/operation/actor/permission fields are server-owned; recursive attempts to inject them into model tool payloads are rejected before Tool Gateway invocation. A stable framework tool-call id contributes to a deterministic idempotency key.

### Filesystem / execute

Virtual roots are limited to `/workspace/input`, `/workspace/work`, `/workspace/output`, exact `/skills/<id>/<version>` sources and policy-scoped `/memory`.

Path traversal is rejected. `ScopedWorkspacePolicy` and Deep Agents `FilesystemPermission` rules both enforce path policy. Each permissions list ends in deny-all. A backend exposing `execute`/`aexecute` is rejected when `sandbox_execute=false`; granted execute additionally requires the LUMI sandbox binding. NODE-21 already contains `DeepAgentsSandboxAdapter` backed by `SandboxRuntimeService`/`DockerSandboxBackend`; production package/DI composition remains gap `DEEP-SANDBOX-005`.

### Context / prompt injection

Root and allowed leaf system prompts contain fixed platform safety plus the immutable Context Compiler constraint block. Dynamic task/delegation content is source-labeled and never treated as trusted platform policy. Pinned project constraints do not depend on message summarization/compaction.

### Exact skills / subagents

The root receives only the exact skill directories referenced by its own config. Every allowed leaf receives only its own exact skill directories; extra or missing materialized skills fail closed. Skill requirements cannot expand effective tool/sandbox/memory permissions.

Deep Agents' implicit `general-purpose` target is replaced by a deterministic disabled runnable. P0 allows root-to-leaf delegation only, leaf memory writes are disabled, leaf skill shell permission is rejected, and sandbox execute cannot coexist with synchronous subagents. Work requiring both execution and delegation must be promoted to durable TaskGraph/LangGraph tasks.

### Budget / large tool results

Tool calls hit a server budget meter before invocation and settle afterward. Large results pass through an offloader so the model receives a bounded summary/reference rather than an unbounded payload. Production chat models must already be wrapped by the NODE-22/NODE-27 model/budget adapter.

### Structured handoff

Root and configured leaves request `AgentTaskResult`. Runtime validation is mandatory. One repair is allowed through `StructuredOutputRepairer`; a second invalid result fails closed. `proposed_operations` remain stored proposals and are never automatically executed or copied into NODE-28 Graph State.

## NODE-28 integration

`DeepAgentTaskExecutor.execute(state)` is compatible with the NODE-28 agentic TaskPort seam. It resolves exact Agent config, exact skills and pinned Context bundle, compiles/invokes a stable nested Deep Agent thread, validates/stores the structured result and returns only safe NODE-28 state keys:

- `artifact_refs`
- `context_refs`
- `errors` when the agent reports failure

The nested thread id is deterministic for run/task/agent exact version and separate from the main control-plane thread.
